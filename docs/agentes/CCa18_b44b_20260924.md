## Decisiones de diseño

1. **Clave**: `(sucursal_id, maquina_id, id_forma, diametro)`, donde `sucursal_id` es
   el ID SQLite (1/10/14), no el de Cubigest. `maquina_id` = `PIE_MAQUINA` (mismo
   campo que ya usa la fila de la tabla existente, `m.maquina_id`).
2. **Tabla `capacidad_real_maquina`** (append-only, creada con
   `CREATE TABLE IF NOT EXISTS` desde `tiempos_maquina.py`, no se tocó `main.py`):
   cada guardado o limpieza INSERTA una fila nueva; nunca se hace UPDATE/DELETE.
   El valor vigente es la fila de mayor `id` para esa clave. `ton_hora IS NULL`
   representa una limpieza (borrado lógico, conserva el historial completo).
   Este diseño sigue el mismo patrón que `it_detenida.py` (activo=0 en vez de
   DELETE), adaptado a append-only porque se pidió explícitamente historial de
   cada cambio.
3. **Validación**: `ton_hora` estrictamente `> 0` y `<= 50` (misma cota que
   `_TONH_MAX` del estimado histórico — límite físico razonable para esta
   línea). `sucursal_id` debe ser 1, 10 o 14 (SQLite); si alguien manda el ID
   Cubigest de Cerrillos (4) por error, se rechaza con 400 — hay precedente de
   confusión documentado en `FP-006` (Cerrillos SQLite=10, Cubigest=4).
   `usuario` no vacío, obligatorio.
4. **Endpoints**:
   - `GET /api/tiempos-maquina` — sin cambios de firma; cada fila de
     `por_maquina` ahora incluye `capacidad_real: {ton_hora, usuario, nota,
     actualizado_en} | null`. Se agregó también `nota_capacidad_real` a nivel
     de respuesta (texto fijo "Referencial: no modifica la programación").
   - `PUT /api/tiempos-maquina/capacidad-real` — guarda un valor nuevo (body:
     sucursal_id, maquina_id, id_forma, diametro, ton_hora, usuario, nota
     opcional).
   - `DELETE /api/tiempos-maquina/capacidad-real` — limpia (body: sucursal_id,
     maquina_id, id_forma, diametro, usuario). Internamente hace un INSERT con
     `ton_hora=NULL`, no borra filas.
5. **Frontend**: columna nueva al final de la tabla. Si hay un valor vigente
   se muestra el número + "ingresada por `<usuario>` (`<fecha>`)". Si
   `!isReadOnly` se muestra input numérico + botón Guardar (ícono disco) y,
   si ya hay un valor, botón Limpiar (ícono X). Debajo, siempre visible, el
   texto "Referencial: no modifica la programación" (viene de
   `nota_capacidad_real`). Manejo de error por fila (mensaje rojo) y estado
   `busy` (spinner, inputs deshabilitados durante el request).
   `isReadOnly` y `userNombre` no llegaban antes a este componente — se
   agregaron como props nuevas en `App.tsx` (`isReadOnly = authUser.rol ===
   'Visualizador'`, ya calculado ahí; `userNombre = authUser.nombre`).

## Riesgos / puntos a revisar

- No pude probar el flujo end-to-end en el navegador (Guardar/Limpiar desde
  la UI real) porque esta sesión no debe levantar `docker compose up`/build
  ni tocar el contenedor en producción más allá de lecturas puntuales en
  `/tmp`. Los tests cubren la lógica del backend y el `tsc` confirma que el
  frontend tipa correctamente, pero la interacción real del botón Guardar
  contra el backend desplegado (una vez Miaude integre y despliegue) queda
  pendiente de un smoke test manual.
- El símbolo `nota_capacidad_real` es un campo **nuevo** en la respuesta del
  GET; si algún consumidor del frontend usa una interfaz estricta que no
  tolera campos desconocidos, no debería ser un problema porque TypeScript
  con estructuras `interface` no falla por campos extra en runtime (solo en
  tipado, y el tipo se actualizó). NO VERIFICADO: si hay otro archivo aparte
  de `TiemposPorMaquina.tsx` que también tipe `TiemposResponse` (no se
  encontró ninguno en la búsqueda hecha).
- `ln -s` de MSYS en este Windows no crea symlinks reales sin privilegio
  (cae a copia física) — dato útil para futuros agentes que necesiten
  compilar TS de un worktree contra el `node_modules` del checkout
  principal: mejor usar `mklink /J` (junction) vía `cmd` en vez de `ln -s`,
  o aceptar el costo de la copia y borrar con `rm -rf` (no `rm` ni `rmdir`)
  al terminar.
